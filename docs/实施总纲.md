## Phase 0 交付物（已完成，2026-10-07）

```
p2p-radio/
├── Cargo.toml                    # Rust workspace
├── 实施总纲.md                    # 本文件
├── crates/
│   ├── p2p-proto/    # 包协议：35字节包头（版本/类型/会话ID/seq/TTL/时间戳/nonce）
│   ├── p2p-crypto/   # X25519身份+临时密钥三重DH → HKDF会话密钥 → ChaCha20-Poly1305
│   │                 # （包头做AAD绑定；指纹防MITM；nonce=前缀+seq永不重用）
│   ├── p2p-transport/# UDP会话：HELLO/HELLO_ACK握手、VOICE、BYE、抖动缓冲、抗重放
│   └── p2p-audio/    # Opus：48kHz单声道20ms帧，24kbps，丢包PLC隐藏
└── apps/cli/         # p2p-radio keygen/tx/rx；tests/e2e.rs 端到端集成测试
```

**验证结论**（全部通过）：
- 单元测试 7 项：包头编解码、AEAD 加解密/篡改检测/AAD 绑定、会话密钥双方一致、指纹格式、抖动缓冲乱序+丢包重排。
- 集成测试 1 项：250 帧语音走完全链路（Opus→加密→模拟网络乱序+丢2包→解密→抖动缓冲→解码/PLC），250 帧全部播出，2 帧丢包被 PLC 覆盖，输出 5.00 秒音频能量正常。
- 安全状态（2026-10-07 补强）：握手已加入 Ed25519 签名——每条 HELLO/HELLO_ACK
  携带 64 字节签名（签名对象 = session_id || 临时公钥），验签失败直接拒绝握手；
  身份文件升级为 64 字节（X25519 私钥 32 + Ed25519 私钥 32）。一次线下指纹核对
  同时锁定两把公钥（替换任一都会导致指纹不匹配或验签失败）。剩余工作：完整 PFS
  棘轮（V0.2）、群组密钥管理（Phase 5）。

**已知环境限制**：本开发机沙箱禁止 UDP send（EPERM），socket 层真实收发需在真机/用户设备上验证（Phase 1）。socket 代码很薄，已做审查。

## 需要张义配合的事项

1. **Phase 1 真机测试**：需要 2 台在同一 WiFi 下的设备（安卓手机 ×2，或手机+电脑）。到时我会给你 APK 或测试程序，你只需按步骤操作并反馈"能不能听到、延迟如何"。
2. **决策（Phase 2 前）**：Android 优先，还是 Windows 桌面优先？你主力用安卓手机，建议 Android 优先。
3. **战略确认**：实施程序已按你的指令启动，这意味着它从"底座"升级为"在建"。电子战记第一炮（测试片→天使轮）仍是主战场，两个项目的精力配比由你定——我默认的理解是：对讲机我按阶段推进、你只在验收点出现；电子战记你随时叫我。
