# Phase 1 真机联调指南（给张义的操作版）

目标：在两台**真实设备**上跑通 UDP 握手 + 语音对讲，验证开发机沙箱里测不到的 socket 层。

> 不用急着一次做完。等你有空、两台设备都在手边时，按顺序一步一步来，
> 每一步做完告诉我结果，我再给你下一步。

---

## 准备（两台设备都要做）

**设备要求**：两台能连同一 WiFi 的电脑（Windows 装 WSL2，或 Linux）。
A 机 = 接收方，B 机 = 发送方。

### 第 1 步：把测试程序拷到两台电脑上

我会给你一个文件 `p2p-radio`（Linux 程序，约几 MB）。
- Windows：放进 WSL2 里（路径如 `~/p2p-radio`），然后 `chmod +x p2p-radio`
- 到时我会给你下载链接，你告诉我两台电脑分别是什么系统，我再细化这一步

### 第 2 步：每台电脑生成自己的身份

两台电脑上**各跑一次**：

```
./p2p-radio keygen
```

会显示一行 `fingerprint: XXXX XXXX XXXX XXXX`。**把两台的指纹都抄下来**（拍照发我也行）。
这是你们俩的"接头暗号"，后面核对用。

### 第 3 步：查 A 机的局域网 IP

A 机上跑：

```
hostname -I
```

记下类似 `192.168.1.105` 的地址（选 192.168 开头的那个）。

---

## 联调（先 A 后 B）

### 第 4 步：A 机开始接收

```
./p2p-radio rx --bind 0.0.0.0:9002 --out out.wav
```

看到 `[rx] my fingerprint: ...` 就停着别动，等 B 机。

### 第 5 步：B 机准备一段语音，开始发送

先准备一段测试语音 `in.wav`（48kHz 单声道；我会给你现成的测试文件，
或者你用手机录一段转格式——到时我教你一键转）。

```
./p2p-radio tx --peer 192.168.1.105:9002 --in in.wav
```

（把 `192.168.1.105` 换成第 3 步查到的 A 机 IP）

### 第 6 步：核对指纹

两边都会打印对方的 `peer fingerprint`。**对照第 2 步抄下来的指纹**：
- A 机看到的 peer 指纹 == B 机的 my 指纹？
- B 机看到的 peer 指纹 == A 机的 my 指纹？

都对 → 继续；不对 → 停下来告诉我（可能有人中间劫持，或连错了设备）。

### 第 7 步：听 out.wav

B 机发完后，A 机的 `out.wav` 就是收到的语音。戴耳机听：
- 能听清吗？有没有卡顿/断续？
- 把感受告诉我（一句话就行，如"清楚，中间卡了两次"）

---

## 故障排查（按顺序查）

| 现象 | 查什么 |
|---|---|
| B 机显示 `handshake timeout` | 两台是否连的**同一个** WiFi？A 机 IP 是否写对？A 机防火墙是否放行 9002/UDP？ |
| 能连上但 out.wav 全是静音 | in.wav 格式是否 48kHz 单声道？（用我给的测试文件先排除） |
| 声音断断续续 | WiFi 信号强度；这是 P2P 的真实表现，记下来告诉我——这是 Phase 3 要优化的 |

---

## 这次联调要回答的三个问题

1. 真实 UDP socket 上，握手/语音/BYE 全流程能跑通吗？
2. 同 WiFi 下延迟体感如何？（<300ms 为 Phase 1 验收线）
3. 丢包时的 PLC 听感能接受吗？

做完把 `out.wav` 和你的体感发我，我来判断 Phase 1 是否验收通过。
